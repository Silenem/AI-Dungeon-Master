# Как работает приключение

Рабочая схема проекта. Go ведёт приключение и применяет правила. ИИ-Мастер понимает свободный ввод, запрашивает игровые проверки и описывает подтверждённый результат. Для генерации Go обращается по API к платному провайдеру или к модели, которую команда обслуживает сама.

## Где живут данные

| Хранилище | Какие данные хранит | Когда используется |
| --- | --- | --- |
| PostgreSQL | Пользователи, исходные листы персонажей, снимки прохождений с последним ходом и очередь заданий для фоновой памяти. | Go загружает снимок при входе, если активной копии нет. Сохраняет по таймеру, после боя и при выходе. |
| Redis | Активное состояние мира и героя, очередь боя, недавние ходы и ходы, ожидающие переноса в очередь памяти. | Go читает и обновляет это состояние во время игры. |
| Elasticsearch | Значимые фрагменты истории с ID и версией сценария, прохождением, ходом, игровым днём и связями с другими фрагментами. | Перед новым ответом Go выбирает уместные воспоминания текущего прохождения. |

Ключ прохождения — `session_id`. Один пользователь может начать два прохождения с одним персонажем. У каждого прохождения будут собственные изменения листа и собственная память. [Схема данных с полями, типами и связями](data-model.md)

## Вход и выход

1. Пользователь открывает приключение. Go проверяет доступ и ищет уже активную сессию в Redis. Если она есть, продолжает с неё.
2. Если активной сессии нет, Go загружает последнее сохранение из PostgreSQL. Для нового прохождения создаёт в Redis копию выбранного персонажа и исходное состояние сценария.
3. В новом прохождении ИИ-Мастер показывает **заранее написанное вступление**. При возвращении Go восстанавливает состояние мира и последний сохранённый ход.
4. После ухода со страницы Go ждёт завершения активного ответа и сохраняет снимок и задания для памяти в PostgreSQL. При следующем входе можно возобновить прохождение с последнего сохранённого момента.

## Обычный режим

1. **Игрок пишет сообщение.** Go передаёт ИИ-Мастеру текущую сцену, состояние героя, недавние реплики и найденные для этой ситуации воспоминания.
2. **ИИ-Мастер разбирает намерение.** Если действие требует проверки или меняет состояние, модель вызывает одну из доступных в текущем режиме игровых функций Go. В функцию передаётся намерение, например попытка открыть замок отмычкой. Go сам выбирает сложность, определяет исход и списывает ресурсы. Неясное намерение можно уточнить у игрока.
3. **Go разрешает проверку или действие.** Проверяет условия сцены и доступные предметы, при необходимости бросает кубик, обновляет состояние мира и проверяет условия глобальных событий. Сохраняет подтверждённый исход в Redis.
4. **ИИ-Мастер отвечает игроку.** Go сохраняет текст ответа вместе с ходом и помечает ход для фоновой обработки памяти. После сохранения задания классификатор может отправить в Elasticsearch обещание NPC, найденную улику или смену отношения к герою.
5. Игрок вводит следующее сообщение. Новый контекст составляется из текущего состояния и подходящих фактов.

Сценарий состоит из фиксированного вступления и глобальных событий с проверяемыми условиями и обязательными последствиями. ИИ-Мастер развивает историю по состоянию мира и действиям игрока. [Сценарий и глобальные события](data-model.md#сценарий-и-глобальные-события)

## Боевой режим

Когда срабатывает условие начала боя, Go фиксирует участников и инициативу. В интерфейсе видны раунд, очередь, текущий участник и то, что ещё доступно на его ходу. Игроку доступны четыре команды.

| Команда | Что проверяет Go |
| --- | --- |
| **Перемещение** | Действует ли герой сейчас и хватает ли движения. После первого боевого теста определим представление позиций и дальности. |
| **Основное действие** | Осталось ли действие, доступен ли выбранный приём и допустима ли цель. Go разрешает атаку или другое основное действие по правилам. |
| **Бонусное действие** | Осталось ли бонусное действие и доступно ли соответствующее умение. Например, боевое применение метамагии расходует этот ресурс. |
| **Пропуск хода** | Герой завершает свой текущий ход и отдаёт очередь следующему участнику. Этой же командой заканчивается ход после уже выполненных действий. |

Интерфейс отправляет выбранную команду прямо в Go. Игрок может совместить движение и основное действие. Go списывает использованное движение и действия по мере выполнения. Он же определяет следующий ход, разыгрывает действия NPC и завершает бой по условиям сцены. ИИ-Мастер описывает события по готовым результатам, как и в обычном режиме. После боя Go возвращает интерфейс к свободному вводу. [Согласованные правила боя](role-model.md#раунд-ход-и-инициатива)

## Сохранение, повторы и память

1. **Обнаруживать выход на сервере.** Клиент может посылать сигнал выхода и периодически подтверждать, что страница открыта. Если клиент пропал, сервер считает сессию неактивной после тайм-аута. Для сохранения Go проверяет, что активный ход завершился. Обработчик закрытия вкладки иногда вообще не срабатывает, например когда мобильный браузер выгружают из памяти. [MDN о закрытии страницы](https://developer.mozilla.org/en-US/docs/Web/API/Window/beforeunload_event)
2. **Делать промежуточные сохранения.** Go сохраняет снимок и задания для памяти после боя и периодически во время игры. Между этими точками Redis можно запускать с AOF и постоянным диском. При потере всего Redis восстановление идёт с последней записи в PostgreSQL. [Сохранение данных Redis](https://redis.io/docs/latest/operate/oss_and_stack/management/persistence/)
3. **Применять команду один раз.** Go допускает один активный ход на прохождение, проверяет ID запроса и версию снимка. Если ответ прервался после попадания, рассказ восстанавливается по сохранённому исходу. Redis очищается после подтверждённого сохранения той же версии при выходе. [Порядок сохранения](data-model.md#как-проходит-сохранение)
4. **Классифицировать память в фоне.** Классификатор получает реплику игрока, подтверждённый исход и текст ответа. Задание в PostgreSQL переживает очистку Redis и повторяется при временном сбое. Значимые фрагменты связываются по времени и содержанию внутри одного прохождения. [Поля фрагмента памяти](data-model.md#индекс-adventure-memory)
5. **Искать по тексту и сущностям.** Go фильтрует по текущему прохождению и подбирает несколько релевантных записей. Игровые факты вроде текущих хитов или наличия ключа Go читает из снимка. [Фильтры Elasticsearch](https://www.elastic.co/docs/reference/query-languages/query-dsl/query-dsl-bool-query) · [Поиск по нескольким полям](https://www.elastic.co/docs/reference/query-languages/query-dsl/query-dsl-multi-match-query)

### Первый сквозной тест

Начать приключение с фиксированного вступления у ворот. Подать сообщение, разрешить его через игровую функцию и вызвать короткий бой вплотную. После сохранения проверить запись значимого факта в память. Во время ответа на следующую команду закрыть страницу, дождаться сохранения и восстановить состояние. При повторе уже принятой команды хиты и очередь ходов должны совпасть с сохранённым результатом.
