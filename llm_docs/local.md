# Локальный ИИ-Мастер и подключение к Go

Для испытаний на Windows начните с Qwen3 4B в Ollama. Модель с теми же весами можно запускать через другой движок, если тот поддерживает её архитектуру и формат. Модель задаёт поведение рассказчика. Квантизация меняет расход памяти и может влиять на качество ответа. Сервер предоставляет игре HTTP API.

## Что потянет имеющийся ПК

Проверка 9 ноября 2026 года показала **NVIDIA GeForce GTX 1070, 8 ГиБ VRAM**, compute capability **6.1**, драйвер **560.94**, около **31 ГиБ доступной системе физической RAM**. В момент проверки `nvidia-smi` показывал около 7 ГиБ свободной VRAM. Скорость генерации и вместимость моделей экспериментально не проверены.

Основные переменные — квантизация, длина контекста и число одновременных запросов. Публичные веса каждой модели имеют собственную лицензию. ## Как подключить локальную модель

**Ollama.** После установки Ollama для Windows и запуска приложения локальный сервер по умолчанию слушает `127.0.0.1:11434`. Для первой загрузки весов нужен интернет. Пример ниже предназначен для ручного прогона после установки. Его работоспособность на этом ПК ещё предстоит проверить. [Windows](https://docs.ollama.com/windows) · [HTTP API](https://docs.ollama.com/api/chat)

```powershell
ollama pull qwen3:4b
```

Проверочный запрос к локальному серверу извлекает намерение. Игрок может описать нестандартный способ, поэтому в примере поле способа остаётся текстовым. Данные из ответа ещё предстоит проверить в Go.

```powershell
$intentSchema = @{
    type = 'object'
    properties = @{
        target = @{ type = 'string' }
        method = @{ type = 'string' }
    }
    required = @('target', 'method')
    additionalProperties = $false
}
$request = @{
    model = 'qwen3:4b'
    stream = $false
    think = $false
    format = $intentSchema
    options = @{ num_ctx = 4096; num_predict = 120 }
    messages = @(
        @{ role = 'system'; content = 'Извлеки цель (target) и способ (method) из фразы игрока. Пиши по-русски. Исход действия определит игровой модуль.' }
        @{ role = 'user'; content = 'Поддеваю засов отмычкой через щель в двери.' }
    )
}
$body = $request | ConvertTo-Json -Depth 8
$reply = Invoke-RestMethod -Method Post -Uri 'http://127.0.0.1:11434/api/chat' -ContentType 'application/json; charset=utf-8' -Body ([Text.Encoding]::UTF8.GetBytes($body))
$reply.message.content | ConvertFrom-Json
ollama ps
```

Проверьте, что цель и способ соответствуют фразе. Наличие отмычки определяется по инвентарю в Go. `ollama ps` показывает, какая доля модели размещена на CPU/GPU. Для рассказчика нужен отдельный запрос с уже рассчитанным исходом. У локальной Ollama есть вывод по JSON Schema, а поддержка управления рассуждением зависит от модели. [Структурированный вывод](https://docs.ollama.com/capabilities/structured-outputs) · [thinking](https://docs.ollama.com/capabilities/thinking) · [диагностика размещения](https://docs.ollama.com/faq)

**LM Studio.** Удобен, когда автор сценария хочет загрузить модель и вручную сравнить ответы через GUI. Встроенный HTTP-сервер предоставляет `/v1/chat/completions` и структурированный вывод, поэтому к той же модели можно обратиться из Go. Использование приложения дома и на работе бесплатно. [Developer API](https://lmstudio.ai/docs/developer/openai-compat) · [JSON Schema](https://lmstudio.ai/docs/developer/openai-compat/structured-output) · [условия](https://lmstudio.ai/blog/free-for-work)

**llama.cpp без Ollama.** После выбора сборки под систему и загрузки подходящего GGUF-файла пример CPU-запуска — `llama-server -m model.gguf -ngl 0 -c 4096`, где `model.gguf` заменяется путём к весам. Сервер полезен, когда нужен явный контроль над размещением слоёв или требуется проверить работу без GPU. [llama-server](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md)

**Другие локальные оболочки.** KoboldCpp поставляется как самостоятельный исполняемый файл с интерфейсом KoboldAI и подходит для ручной проверки рассказчика на GGUF. Docker Model Runner удобен команде, которая уже использует Docker и хочет доставлять веса как OCI-артефакты. LocalAI предоставляет общий HTTP API для нескольких движков. Во всех трёх случаях генерация использует ресурсы выбранной машины, а поддержка GPU и конкретной модели зависит от сборки и бэкенда. [KoboldCpp](https://github.com/LostRuins/koboldcpp) · [Docker Model Runner](https://docs.docker.com/ai/model-runner/) · [LocalAI](https://localai.io/)

## Один игровой код для разных поставщиков

| Задача | Go-бэкенд | Что зависит от поставщика |
| --- | --- | --- |
| Разобрать действие | Посылает фразу и видимые игроку факты. Проверяет, что ответ можно разобрать, что цель существует и что метод допустим в сцене. Неясная фраза приводит к уточнению. | Модель, адрес API, способ авторизации, формат передачи JSON Schema и поддержка ограничения вывода. |
| Разрешить ход | Читает инвентарь и способности, выбирает характеристику, делает бросок, сохраняет результат. | Этот этап выполняется без LLM. |
| Описать результат | Передаёт сохранённые изменения и факты об NPC. При повторной генерации использует тот же исход. | Генерация по частям, длина ответа и время до первых слов. |

Ключ облака хранится на сервере команды. Для автономного режима Go обращается к локальному адресу. Для облачного режима даже при OpenAI-совместимом маршруте отдельно проверяются корневой URL, идентификатор модели, авторизация и поддержка функций. Например, локальная Ollama принимает схему в поле `format`, GigaChat документирует `response_format.schema`, а LM Studio поддерживает формат `/v1/chat/completions`. Когда провайдер поддерживает строгую схему, можно ограничить форму ответа. Смысл игрового действия по-прежнему проверяет Go. [Ollama](https://docs.ollama.com/api/openai-compatibility) · [GigaChat](https://developers.sber.ru/docs/ru/gigachat/guides/structured-output) · [LM Studio](https://lmstudio.ai/docs/developer/openai-compat/structured-output) · [Yandex Chat Completions](https://aistudio.yandex.ru/ru/docs/ai-studio/api/Chat-Completions/createChatCompletion)
